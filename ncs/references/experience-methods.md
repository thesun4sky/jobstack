# 경험 소재화 방법론 (experience-methods)

경험을 서류·면접용 소재로 바꾸는 공통 절차의 단일 정의. 4년/60건+ 첨삭에서 검증된 방법론이며, ETHOS.md가 철학(왜)이라면 이 문서는 실행 절차(어떻게)다. 소비 스킬은 해당 Phase에서 "§N을 적용하라" 형태로 섹션 단위로 인용한다.

---

## §1. 경험 전환 6단계

**적용 시점**: 소재 발굴·초안 작성 (경험 1건을 카드 1장으로 구조화할 때)

| 단계 | 질문 | 산출 |
|---|---|---|
| 1. 이름 | 이 경험을 한 줄로 부르면? | 경험 제목 |
| 2. 문제 | 무엇이 문제였나? (누가·언제·얼마나) | 문제 정의 |
| 3. 역할 | 그중 내 몫은 정확히 어디까지였나? | 역할 범위 |
| 4. 바꾼 행동 | 내가 무엇을 다르게 했나? | 구체 행동 |
| 5. 검증 가능한 변화 | 무엇이 달라졌고, 어떻게 확인했나? | before→after |
| 6. 직무 연결 | 지원 직무의 어떤 일과 닿아 있나? | 직무 태그 |

6단계 중 하나라도 비어 있으면 그 경험은 아직 소재가 아니다 — 비어 있는 단계를 질문으로 채운다.

## §2. 문제·역할·행동·결과 4분리

**적용 시점**: 초안 작성·첨삭 (한 문장에 여러 층위가 섞였을 때)

문제/역할/행동/결과를 각각 별도 문장으로 분리한다. 팀 성과와 본인 기여를 한 문장에 섞지 않는다.

**피해야 할 표현 5종** (감지 즉시 4분리로 재작성):

| 피할 표현 | 문제점 |
|---|---|
| "다양한 경험을 통해" | 경험이 특정되지 않음 |
| "책임감을 가지고" | 행동이 없음 |
| "소통 능력을 발휘해" | 무엇을 조율했는지 없음 |
| "많은 것을 배웠습니다" | 결과가 없음 |
| "팀에 기여했습니다" | 본인 몫이 없음 |

## §3. 수치 폴백 5기준 + 대체 4종

**적용 시점**: 수치화 코칭 (성과 숫자가 없다고 할 때 — 날조 금지, guardrails §1)

숫자가 없어도 아래 5기준을 **위에서부터 순서대로** 적용해 근거를 찾는다:

| 순위 | 기준 | 예시 |
|---|---|---|
| 1 | 전후 변화 | 정성이라도 before→after ("수기 정리 → 양식화") |
| 2 | 역할 범위 분리 | 전체 중 내 몫 ("API 12개 중 8개 담당") |
| 3 | 정성 근거 | 사수 피드백, 내가 만든 양식이 계속 쓰임 |
| 4 | 작은 검증 가능 숫자 | "3주간 문의 12건 유형 정리" > "수백 건 처리" |
| 5 | 면접 설명 가능성 | 1분간 설명 못 하는 수치는 쓰지 않는다 |

**수치 대체 4종**:

| 유형 | 예시 |
|---|---|
| 범위 | 담당 API 개수 |
| 빈도 | 주 1회 배포 |
| 전후 비교 | 정성이라도 before→after |
| 담당 규모 | 고객사 15곳 |

## §4. 추상어→질문 전환표

**적용 시점**: 첨삭 (추상어를 발견하면 삭제하지 말고 질문으로 전환해 구체 경험을 캐낸다)

| 추상어 | 전환 질문 |
|---|---|
| 책임감 | 끝까지 맡아서 처리한 일이 무엇인가? |
| 소통 | 누구와 누구 사이의 이해 차이를 줄였나? |
| 꼼꼼함 | 어떤 오류·누락을 얼마나 줄였나? |
| 문제해결력 | 문제를 어떻게 정의했나? |
| 성장 | 그 전과 후에 무엇이 달라졌나? |

## §5. 약한 문장 5유형 + 보강

**적용 시점**: 첨삭 (문장 단위 진단)

| 약한 문장 유형 | 보강 방향 |
|---|---|
| "~을 좋아합니다" | 좋아해서 실제로 한 행동 사례로 교체 |
| "열심히 했습니다" | 역할을 구체화 (무엇을·어디까지) |
| "성장했습니다" | 전후 비교로 교체 |
| "소통했습니다" | 조율 유형을 특정 (전달·정리·설득·조정 중 무엇) |
| "책임감 있게" | 맡은 범위 + 문제 발생 시 처리 기준으로 교체 |

## §6. 어조 전환 3공식

**적용 시점**: 최종 다듬기 / 면접대비 (공식은 ETHOS.md와 동일, 예시는 실측 수치로 구체화한 것 — 아래 표가 단일 소스)

| 공식 | Before | After |
|---|---|---|
| 희망→실행 | "~하고 싶습니다" | "~하고 있습니다" / "~해 왔습니다" |
| 감정→행동 | "흥미를 느꼈습니다" | 구체적 프로젝트와 성과 서술 |
| 과정→결과 | "밤새 공부했습니다" | "응답시간 350ms → 15ms 개선을 달성했습니다" |

적용 순서: 문장별로 ①어느 공식에 해당하는지 판정 → ②After 형으로 재작성 → ③재작성에 필요한 사실이 없으면 §4의 질문으로 사용자에게 확인 (추정 금지).

**면접대비 인용**: 면접 답변 골자를 구성할 때(mock-interview 등)도 §1의 경험 카드와 §6의 After 형 문장을 그대로 재사용한다 — 서류와 면접의 어조·근거를 일관되게 유지하기 위함(ETHOS "면접까지 일관된 스토리").

## §7. STAR-R 서술 프레임 (R = 입사 후 적용)

**적용 시점**: 자소서 결이요의 '요'·입사 후 포부·기업 맞춤 서류·면접 "입사하면 어떻게 기여할 건가요" 답변. 이력서 본문에는 쓰지 않는다(이력서의 R 은 Result 까지).

| 글자 | 뜻 | 카드 필드 | 비고 |
|---|---|---|---|
| S | Situation | `problem`(누가·언제·얼마나) | §1 2단계 |
| T | Task | `problem` + `role`(내 몫) | §1 3단계 |
| A | Action | `action` | §1 4단계 |
| R | Result | `change` + `numbers` | §1 5단계·§3 |
| R | 입사 후 적용 | `apply_plans[].plan` (+`basis`·`source`) | 기업당 1문장, 아래 규칙 |

두 번째 R 은 **입사 후 적용**이다 — 일반 STARR·STAR-L 이 마지막 글자를 '성찰·배운 점'으로 두는 것과 의도적으로 다르다. "많은 것을 배웠습니다" 류 마무리는 §2 피해야 할 표현이며, 감상은 결과가 아니라 다음 **행동 변화**로 바꾼다(cover-letter 배운 점 규칙·retro 작성 규칙과 같은 계열). 저장 형식은 `experience-card-schema.md`(`apply_plans`)가, 저장은 `jobstack-exp.mjs apply` 가 맡는다.

**R 작성 규칙 4가지:**

1. **근거 1개 이상** — 기업분석(`/company_research`) 캐시의 키워드 체크리스트·'이미 팀원처럼' 화두·공고 문구 중 하나를 `basis` 에 원문 그대로 인용하고, 출처 파일명·기준일을 `source` 에 병기한다. 근거가 없으면 R 을 쓰지 않고 `/company_research` 를 안내한다(guardrails §1·§5 — 기업 과제를 훈련 데이터로 채우지 않는다).
2. **형식 한 문장** — "[기업의 과제·키워드]에 [카드의 행동·변화]를 적용해 [기대 변화]". 어조는 §6 희망→실행("~하고 싶습니다" 대신 "~을 적용해 ~을 줄인다/앞당긴다"). 기대 변화는 카드의 검증된 변화 범위 안에서만 말하고 새 수치를 만들지 않는다.
3. **회사명 치환 테스트** — humanize-check §1 (a)와 같다. 회사명을 경쟁사로 바꿔도 성립하면 실패 → `basis` 를 더 구체적인 키워드로 바꿔 재작성한다.
4. **감상 뒤에 잇지 않는다** — 카드·초안에 감상형 마무리가 남아 있으면 먼저 §2·§5 로 행동 변화로 고친 뒤 R 을 잇는다. R 은 장식이 아니라 결이요의 '요'다.

**질문 2개** (근거 확보용, 각 1회 — 답이 없으면 R 을 생략한다):
- "지원 중인 기업이 있나요? 그 기업의 기업분석 결과(캐시)가 있나요?"
- "이 경험이 그 기업의 어떤 과제·키워드에 닿나요?" — `basis` 후보는 사용자 답변과 캐시 요약 블록에서만 고른다.

| Before | After |
|---|---|
| "이 경험을 바탕으로 귀사에서도 성장하겠습니다" | "결제 응답 지연 과제(캐시 키워드 '결제 안정성', 토스-2026-09-06.md)에 Redis 캐싱 설계 경험을 적용해 p95 지연 원인 분석부터 맡는다" |
| "많은 것을 배웠고 입사 후에도 열심히 하겠습니다" | 먼저 행동 변화로 교체("작업 전 담당자·검수 기준을 먼저 합의한다") → 그 뒤 "공고 문구 '장애 회고 문화'에 그 합의 절차를 적용해 회고 액션 누락을 줄인다" |
