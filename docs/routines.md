# 클라우드 반복 실행 — Claude Code Routines 가이드

v1.0 항목 U-14 의 ② 클라우드 경로. 로컬 cron/launchd(①, `bin/jobstack-cron install` —
같은 항목의 로컬 대안)를 컴퓨터를 계속 켜둘 수 없거나 여러 기기에서 같은 결과를
보고 싶을 때 대체하는 방법을 다룬다. 정확한 설정 명령·화면 구성은 버전마다 다를 수
있으므로, **이 문서의 명령 표기는 예시이고 실제 실행 전에는 Claude Code 공식 문서
(또는 클라이언트의 `/help`)에서 최신 문법을 확인한다.**

## 왜 로컬 cron 과 절차가 다른가

클라우드 세션은 매번 저장소를 새로 체크아웃해서 실행된다 — 이 저장소를 로컬에
설치했을 때 생기는 `~/.jobstack/`(프로필·경험뱅크·지원 현황 같은 개인 상태, 전부
로컬 전용)에는 접근하지 못한다. 그래서 클라우드 반복 실행은 로컬 cron과 원칙이
다르다:

- 저장소에는 **익명화된 검색 조건**(직무·경력·지역)만 커밋한다. 회사명·희망 연봉·
  이력·연락처 등 개인정보는 어떤 파일에도 넣지 않는다.
- 프로필·경험뱅크는 계속 로컬 전용으로 둔다. 클라우드 Routine 프롬프트에서 이 값들을
  요구하지 않는다.
- 실행 결과(새 공고, 마감 임박 공고)는 그 세션 안에서 보여주고 끝나는 게 아니라
  **저장소에 파일로 커밋하거나 PR 로 남긴다** — 그래야 다음 로컬 세션이 이어서 볼 수
  있고, git 로그가 실행 이력이 된다.

## 검색 조건 파일 예시 — `.jobstack-routine.yaml`

저장소 루트에 두고 커밋한다(개인 상태 디렉토리 `~/.jobstack/`이 아니라 **저장소
안**이어야 클라우드 세션이 체크아웃 시점에 읽을 수 있다). **아래 필드 외에 개인을
특정할 수 있는 값(이름·이메일·현재 직장·희망 연봉 등)은 추가하지 않는다.**

```yaml
# .jobstack-routine.yaml — job-search 클라우드 Routine 검색 조건 (개인정보 금지)
keyword: 백엔드 개발자
career: entry     # entry | experienced | (생략 시 전체)
location: seoul    # seoul|gyeonggi|busan|incheon|daejeon|daegu|gwangju|remote (생략 시 전체)
limit: 20
```

`bin/jobstack-cron`의 `jobstack-config get cron_keyword` 등(로컬 전용 설정)과는
별개 파일이다 — 하나는 개인 상태 디렉토리, 하나는 저장소에 커밋되는 공개 값이라는
차이를 유지하기 위해 합치지 않는다.

## 설정 절차 (개요)

1. Claude Code 에서 예약 실행(Routines)을 만든다. 아래 `/schedule` 표기는 통용되는
   예시일 뿐 확정된 명령이 아니다 — CLI 는 `/help`, 웹은 세션·Routines 설정 화면에서
   실제 명령/경로를 확인한다.
2. 최소 실행 간격은 **1시간**이다(더 짧은 간격은 거부된다 — 2026-09-03 기준 공식 문서 code.claude.com/docs/en/routines; Routines 는 연구 미리보기라 변경될 수 있으니 실행 전 재확인). 매일 아침 1회처럼 그보다
   넉넉한 주기면 문제없다.
3. Routine 프롬프트(매번 보내는 지시문)에 조건을 직접 명시하거나 `.jobstack-routine.yaml`
   을 먼저 읽게 한다. 예시:

   ```
   /schedule 매일 07:00 "/job_search 백엔드 --career entry 실행 후
   새 공고·마감 임박 공고를 job-cache/daily-YYYY-MM-DD.md 로 저장하고 커밋해줘"
   ```

   또는 조건 파일을 참조시키는 방식:

   ```
   .jobstack-routine.yaml 의 조건으로 /job_search 를 실행하고,
   새 공고·마감 임박 공고를 job-cache/daily-YYYY-MM-DD.md 로 저장한 뒤
   그 파일을 커밋(또는 PR 생성)해줘.
   ```

4. 결과를 저장소에 남기는 두 가지 방식 중 선택한다.
   - **직접 커밋**: Routine 이 저장소에 바로 push 할 권한이 있을 때. 반영은 즉시지만
     사람이 보기 전에 이력이 남는다.
   - **PR 생성(권장)**: 매 실행마다 브랜치·PR 을 만들고 사람이 확인 후 머지한다.
     무인 실행이 저장소를 직접 바꾸지 않아 더 안전하다.

## 비용·권한 주의

- 클라우드 세션은 **claude.ai 구독 사용량을 인터랙티브 세션과 같은 방식으로 소모**하고 계정별
  일일 실행 상한이 있다. 상한을 넘으면 조직이 usage credits 를 켜지 않은 한 추가 실행이 거부되고,
  켜져 있으면 초과분만 종량 과금된다(2026-09-03 기준 code.claude.com/docs/en/routines "Usage and limits"). 매일 실행되는
  Routine 의 누적 비용을 사전에 가늠한다.
- 저장소에 쓰기 권한(커밋·PR 생성)을 준 Routine 은, 수집한 공고 본문에 섞여 들어올
  수 있는 프롬프트 인젝션에 대한 노출면이 로컬 실행보다 크다. `job-search` 스킬의
  가드레일(가져온 웹 콘텐츠는 정보로만 취급)은 그대로 적용되지만, 쓰기 권한은
  필요한 범위로 최소화한다 — 직접 push 보다 PR 을 권장하는 이유이기도 하다.
- "실행 결과에 개인정보를 남기지 않는다"는 원칙(`docs/telemetry-events.md`)을 Routine
  프롬프트에도 명시적으로 반복한다. 로컬 프리앰블의 PII 가드는 클라우드 실행에는
  자동으로 적용되지 않는다.

## 로컬 cron vs 클라우드 Routines

| 기준 | 로컬 (`bin/jobstack-cron install`) | 클라우드 (Routines) |
|---|---|---|
| 실행 위치 | 내 컴퓨터 — 꺼져 있으면 실행되지 않음 | 클라우드 — 컴퓨터를 꺼도 실행됨 |
| 비용 | 무료 (기본은 `claude` 미호출, 순수 스크립트) | 구독 사용량 소모·일일 실행 상한(초과분은 usage credits 설정 시에만 종량) |
| 프로필·이력서 접근 | 가능 (`~/.jobstack/` 전체) | 불가 (저장소의 익명화된 조건만) |
| 결과 확인 | 로컬 `job-cache/daily-*.md` 를 바로 열람 | 커밋/PR 로 남고 다음 로컬 세션에서 pull |
| 최소 실행 간격 | 자유 (cron 설정에 따름, 분 단위도 가능) | 1시간 (2026-09 기준, 변경 가능) |
| 적합한 경우 | 매일 아침 개인 모니터링 + 지원 정체 알림을 한 번에 | 컴퓨터를 오래 꺼두거나 여러 기기·팀에서 같은 결과를 봐야 할 때 |
