# 제도·지원금·권리 체크리스트 — 실행 시 확인

tracker(탈락 후 안내)·retro(탈락 건 마무리)·mock-interview(AI 전형 권리 안내)·salary(협상 근거)가 Read 한다. 권리·제도 안내는 **이 문서 한 곳에만** 두고 각 스킬은 요약해 전달한다(스킬 본문에 조문·요건을 따로 적지 않는다).

## 쓰는 규칙

1. **수치·기한·금액·자격 요건은 이 문서에 적지 않는다.** 실행 시 WebSearch 로 공식 출처(law.go.kr, work24.go.kr, moel.go.kr, 해당 기관 공고)를 확인해 출처 URL 과 기준일을 병기하고, 확인하지 못한 항목은 "(확인 필요)" 로 남긴다(가드레일 §3·§5).
2. **`상태` 열을 그대로 믿지 않는다.** `시행` 은 아래 `조문 확인일` 에 법령 원문에서 조문이 있음을 확인했다는 뜻이고, 그 뒤 개정됐을 수 있다. `논의 중` 은 법안·정부안 단계라는 뜻이며 통과 여부는 매번 확인한다. 통과를 전제로 안내하지 않는다.
3. **법률 자문이 아니다.** "이런 제도가 있고 여기서 확인·신청할 수 있다"까지만 안내하고, 개별 사건의 위법 여부 판단이나 청구 성공 가능성은 말하지 않는다. 분쟁이 예상되면 고용노동부 상담(국번 없이 1350)이나 개인정보 침해 신고 창구 같은 공식 창구를 안내한다.
4. 권리 안내는 건당 1회, 짧게 한다. 탈락 직후에 권리 목록을 통째로 나열하지 않는다 — 기본 1줄에 해당되는 것 1개를 더하는 정도로 하고, 자세한 절차는 사용자가 원할 때 확인해 제공한다.

조문 확인일: 2026-11-10 (law.go.kr 현행 법령 기준 — 채용절차의 공정화에 관한 법률, 개인정보 보호법, 인공지능 발전과 신뢰 기반 조성 등에 관한 기본법)

## 탈락 후 권리 (tracker·retro — 불합격·지원취소 전환 뒤 선택 안내)

| 항목 | 상태 | 근거 | 실행 시 확인할 것 | 안내 방식 |
|---|---|---|---|---|
| 채용서류 반환 청구 | 시행 | 채용절차법 제11조 | 청구 기간·방법·보관 기간(시행령), 홈페이지·전자우편 제출 서류 등 예외 | 요건에 해당하면 청구 방법을 한 줄로 |
| 채용 여부 통지 | 시행 | 채용절차법 제10조(고지), 제8조(일정·과정 고지) | 통지가 없을 때의 문의 창구. 통지 의무 위반에 대한 제재 규정 유무 | 결과를 못 받았으면 정중한 문의 문구 예시 1개 |
| 채용심사비용 부담 금지 | 시행 | 채용절차법 제9조 | 예외 승인 여부(공고에 명시됐는지) | 비용을 요구받은 경우에만 안내 |
| 직무와 무관한 개인정보 요구 금지 | 시행 | 채용절차법 제4조의3 | 지원서가 요구한 항목이 금지 범위에 드는지 | 해당 항목을 요구받은 경우에만 안내 |
| 적용 범위 | 시행 | 채용절차법 제3조 | 사업장 상시 근로자 수 기준, 공무원 채용 제외 | 위 네 항목을 안내하기 전에 적용 대상인지 먼저 확인 |
| 개인정보 파기 요청 | 시행 | 개인정보 보호법(파기·처리정지 권리) | 지원 시 동의한 보유 기간, 파기 요청 경로 | 기업 채용 페이지의 개인정보 처리방침 확인 |
| 불합격 사유·피드백 문의 | 의무 아님 | 기업 정책 | 기업이 피드백을 제공하는지 | 정중한 문의 문구 예시 1개 |
| 면접비·교통비 | 의무 아님 | 공고 문구 | 공고에 명시됐는지 | 공고 문구 확인 |

## 갱신 주기

- 분기 1회, 그리고 **매년 12월(다음 해 예산·요율 확정 뒤)** 에 `상태` 열과 `조문 확인일` 을 다시 확인한다. 알림 자동화는 후속 과제다 — `bin/jobstack-cron` 에는 아직 분기 알림이 없다.
- 항목이 폐지·개명되면 행을 지우지 말고 `상태` 를 `폐지(확인일)` 로 바꾼 뒤 다음 갱신 때 지운다.
- 이 문서에 항목을 추가할 때도 수치는 넣지 않는다. `test/lint-conventions.sh` 의 시장 수치 검사는 SKILL.md 만 보므로, 이 문서는 사람이 지킨다.
